# Types de publication

Cinq types. Vous choisissez le type **à la création** : cela change les champs du formulaire et les boutons sur la publication.

## Vue d’ensemble

| Type | But | Particularité |
| --- | --- | --- |
| Discussion | Échange libre | Commentaires et likes classiques |
| Application | Faire essayer un produit | Lien d’essai + retours signés ou anonymes |
| Entraide technique | Résoudre un problème | Réponses + acceptation + « Ça m’a aidé aussi » |
| Aide au choix | Trancher entre options | Avis + décision de l’auteur |
| Sondage | Mesurer une opinion | Vote + résultats sans montrer qui a voté quoi |

---

## 1. Discussion

Titre, texte, images optionnelles. Idéal pour annonces, opinions, partages sans parcours particulier.

---

## 2. Application partagée

Vous partagez une app avec un **lien d’essai** (http ou https). Le bouton **Essayer l’app** ouvre ce lien.

### Retours

| Mode | Ce que voient les autres |
| --- | --- |
| Signé | Votre nom / profil |
| Anonyme | « Anonyme » — votre identité n’apparaît pas |

En anonyme : pas de message privé vers l’auteur du retour. Les réponses publiques et les likes restent possibles.

Sans image, la publication reste acceptée. Un lien invalide est refusé.

---

## 3. Entraide technique

Vous décrivez un problème (texte, code, captures). Les **réponses techniques** se distinguent des commentaires ordinaires.

| Action | Qui | Règle |
| --- | --- | --- |
| Proposer une réponse | Les membres | Réponse dédiée sous la question |
| Accepter une réponse | L’auteur de la question | Une réponse acceptée |
| « Ça m’a aidé aussi » | Les autres | Signale que la réponse aide aussi |

---

## 4. Aide au choix

Vous proposez plusieurs **options**. Les membres donnent un avis argumenté. **Vous** retenez ensuite l’option choisie.

Utile pour : stack, design, roadmap, naming…

---

## 5. Sondage

Vote simple ou multiple selon le réglage. Les résultats montrent les scores **sans** afficher qui a voté pour quoi. Vous pouvez fermer le sondage quand c’est fini.

---

## Conseils

- Choisissez le bon type dès le départ : ça conditionne toute la suite.
- Pour du support technique, préférez **Entraide** plutôt qu’une Discussion.
- Pour un test produit, **Application** + retours anonymes si vos testeurs préfèrent la discrétion.
