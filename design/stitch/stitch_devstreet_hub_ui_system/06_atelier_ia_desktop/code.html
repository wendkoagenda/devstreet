Export CSV avec StreamingHttpResponse

Contexte terrain : Dans les marchés ruraux et zones à connectivité intermittente, le volume cumulé des transactions d'inventaire journalier dépasse 40 000 lignes. L'utilisation d'une réponse HTTP classique provoquerait un débordement mémoire (OOM) sur le conteneur applicatif bas coût. Le streaming chunk par chunk est impératif.

data_object Points d'ancrage vérifiés dans le dépôt

apps/inventory/models.py class StockMovement
apps/inventory/views.py MovementListView

format_list_numbered Étapes techniques séquentielles

  1. 01. Créer le service d'itération génératrice : Implémenter un générateur Python tirant parti de .iterator(chunk_size=1000) sur l'ORM Django pour streamer les lignes par paquets sans charger le QuerySet complet en RAM.
  2. 02. Brancher la vue Django & Encodage UTF-8 BOM : Instancier StreamingHttpResponse avec les headers text/csv; charset=utf-8-sig pour assurer l'ouverture immédiate sans corruption d'accents sur tableurs locaux.
  3. 03. Prévoir la persistance IndexedDB de secours : Mettre en mémoire tampon locale les mouvements générés pendant les ruptures réseau avant déclenchement de l'export.

  • Séparateur décimal : virgule (,) ou point (.) selon les paramètres régionaux des postes comptables.
